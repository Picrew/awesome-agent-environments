# 分类设计与迭代

第一版采用“博客 → 论文 → GitHub”作为一级入口，主题偏向训练环境。2026-10-08 的扩展版改为 **研究大类 → 研究小类 → 工作 → 配套资源**。范围同时包含独立环境构造、任务合成、数据采集与评测，不以训练收益作为收录条件。

| 大类 | 小类 | 分类依据 |
| --- | --- | --- |
| 环境与任务构建 | 技能驱动、需求驱动、仓库驱动、Web／GUI 合成、结构化工具／业务世界、程序化任务、学习式模拟器 | 新交互场景或任务怎样产生 |
| 交互数据与经验生产 | 探索／回放／反向合成、轨迹筛选／数据配方、轨迹采集／检查 | 经验怎样产生、保存并变得可用 |
| 环境基础设施 | 接口／适配器／注册库、沙箱／执行 | 环境怎样接入、运行与复用 |
| 领域环境与评测基准 | 软件／终端／技能、GUI、工具／企业、游戏／推理、科学／具身 | 主要贡献是某领域交互底座或测量基准 |
| 自适应与质量控制 | 课程／共演化、验证器／契约／失败审计 | 怎样选择有效难度与可信反馈 |
| 综述与研究地图 | 环境扩展与演化综述 | 汇总机制、概念和研究证据 |

一级按主要研究职责划分，二级在各职责内细分。现实工作可能跨多个环节，每项工作仅选一个主位置，专题表和详情互链承担交叉引用，避免目录重复膨胀。领域基准按交互形态分组，是该大类内部的分类依据，并不把所有同领域工作强塞在一起。

具体取舍：Skill2Env / SkillSynth 归技能构建；Envs-FORGE 以奖励和种子通过率选择合成动作，归自适应课程；CalibForge 以求解器校准为主要贡献，归自适应。AgentTrek / OS-Genesis 主要产生任务与轨迹，归经验生产。WebForge 虽然产出评测集，但核心是网站合成，归 Web／GUI 构建。TerminalWorld 的录制还原归逆向合成，不能和技能版 Terminal-World 合并。DeNovoSWE 的求解任务是从零写仓库，但任务源依托已有软件，归仓库驱动构建。

机器字段：`groups` 保存大类；`categories[].parent` 指向大类；每条资源的 `category` 指向小类。`work_id` 汇总同一工作的资源；`kind` 表示论文／博客／项目；`environment_type` 表示执行形态；`evidence_type` 表示报告的实验或贡献类型，取代过窄的 `training_evidence` 字段。

生成器按大类和小类导航，资源分表展示，同一工作通过详情互链；使用自然 Markdown 标题锚点。校验器拒绝未知父类、未知小类、重复资源和同一工作分属不同小类的错误。文章按已确认日期排列，仓库按 star 快照排列；不将 star 当成研究质量排名。
