# 研究重点：规模化高质量环境与有效训练数据

这份调研围绕两个问题展开：**如何大量制造值得学习的环境？如何利用环境和内容生产让模型学得更好的数据？** 环境可以先作为独立产物，数据可以用于 SFT、RL 或后续研究；但"训练得好"需要单独的实验验证。

下面区分三种表述：论文/博客披露的机制，来自已核验目录；研究取舍是本目录的判断；"我们的设想"仅指基于本次讨论提出的待验证方案，不暗示已有内部成果或已证明的新颖性。

## 一、规模化生产高质量环境

目标产物是可以反复采样任务、恢复状态、执行动作并验收结果的环境与任务库。扩大规模不能只增加提示词改写或同一模板的实例数；质量也不能只用"容器能启动"衡量。

| 切入点 | 要解决的具体问题 | 应记录的产物或指标 |
| --- | --- | --- |
| 素材与构造路线 | 技能、需求、教程、文档、仓库、PR 怎样变成任务与状态？ | 来源谱系、能力覆盖、任务蓝图、初始化资源、可执行环境 |
| 数量与覆盖 | 增加的是环境家族、实例、任务还是轨迹？是否只是近重复？ | 分开报告各计数；去重后覆盖；构造吞吐；每个合格环境的成本 |
| 可执行与可解 | 能否稳定初始化/重置？参考解是否真的完成任务？ | 构建率、重放/重置通过率、参考解通过率、失败归因 |
| 验收与真实性 | verifier 是否检查真实目标？有无答案泄漏、捷径或错误奖励？ | 独立抽检、反例测试、绕过率、状态及工具语义一致性 |
| 有效难度与多样性 | 对当前学习者是否既可学又有挑战？哪些能力缺口没有覆盖？ | 分模型成功率、难度分布、来源/技能覆盖和近重复比例 |
| 批量迭代 | 哪些坏任务修复、重造或丢弃？如何避免只优化一个求解器？ | 每轮净新增合格任务、修复成本、跨求解器验证与版本记录 |

这些指标是拟采用的分析口径，不是目录中每篇论文都已报告的统一评测结果。核心目标可以先表述为：**在给定构造预算下，得到更多不同、可靠、可学习的环境**；暂不把多个指标揉成未经验证的单一分数。

代表材料：[Envs-FORGE](https://arxiv.org/abs/2608.14312)、[SWE-Universe](https://arxiv.org/abs/2602.02361)、[daVinci-Env / OpenSWE](https://arxiv.org/abs/2603.13023)、[Agent-World](https://arxiv.org/abs/2604.18292)、[EnvScaler](https://arxiv.org/abs/2601.05808)、[CLI-Universe](https://arxiv.org/abs/2606.22883)、[CalibForge](https://arxiv.org/abs/2608.06352)、[Endless Terminals](https://arxiv.org/abs/2601.16443)。Poolside 的工程文章适合看仓库到可运行镜像；Reflection 适合看来源、质量过滤与训练反馈迭代。它们提供机制披露，不等于完整流水线已开放。

## 二、合成有效的训练数据

输入既可以是已有环境，也可以是技能、教程、文档与需求。研究重点是任务从哪里来、交互如何产生、哪些轨迹留下、数据怎样混合，以及训练收益来自哪一环。

| 阶段 | 关键内容 | 要避免的混淆 |
| --- | --- | --- |
| 内容变任务 | 技能依赖、教程步骤、需求约束、仓库事实用于生成目标与场景 | 只有自然语言题目，未必具备可执行上下文 |
| 环境中采样 | 教师示范、探索、回放、逆向合成、多候选求解与修复 | 更多采样次数不自动带来更多独立学习信号 |
| 验证与筛选 | 执行验收、技能实际使用、轨迹去重、长度与难度控制 | 成功率高不等于数据覆盖好；失败也可能来自坏环境 |
| 数据配方 | 教师选择、任务/领域混合、成功与修复示范、课程次序 | teacher 更强、token 更多、harness 更好可能是混杂因素 |
| 训练接入 | 区分静态 SFT 轨迹、离线经验与在线 RL 的交互任务分布 | 一个发布的轨迹集不能自动称为可直接在线 RL 的环境库 |
| 收益验证 | 独立任务成功率、跨来源/技能泛化、成本与稳定性 | 训练 reward、同源验证分数和真实泛化不是同一指标 |

**SFT 分支**：构造任务，采集示范或修复过程，验证、过滤、去重，再形成监督样本。需比较相同训练预算下数据质量与多样性的贡献。Skill2Env、Terminal-World 等在本目录记为 SFT 实验，不能改写成已经验证在线 RL。

**RL 分支**：除生成任务或离线经验外，在线 RL 需要能够按当前策略持续交互的环境与可靠奖励；离线 RL/经验回放能否复用固定轨迹则取决于算法和数据条件。环境生成器、任务采样分布、反馈机制和课程是这一分支的数据生产组成。不能只把 SFT 数据换个标签就称为 RL 数据。

代表材料：[Skill2Env](https://arxiv.org/abs/2609.33772)、[Terminal-World (skills)](https://arxiv.org/abs/2605.20876)、[NexForge](https://arxiv.org/abs/2607.14186)、[OpenThoughts-Agent](https://arxiv.org/abs/2606.24855)、[TerminalTraj](https://arxiv.org/abs/2602.01244)、[AgentTrek](https://arxiv.org/abs/2412.09605)、[OS-Genesis](https://arxiv.org/abs/2412.19723)、[RandomWorld](https://arxiv.org/abs/2506.11045)、[DreamGym](https://arxiv.org/abs/2511.03773)、[VERA](https://arxiv.org/abs/2610.05923)。目录中的实验类型标签区分 SFT、RL 和联合实验，训练效果仍以各论文的设置与局限为准，本调研没有复现实验。

## 三、把两条主线连起来，但分开验证贡献

拟研究的完整链路是：

内容/技能/仓库 → 任务与环境构建 → 质量检查与修复 → 环境/任务池 → 轨迹采样与筛选 → SFT 或 RL → 独立评测 → 决定下一轮生成什么。

前半段解决"有没有足够好的练习场"，后半段解决"这些练习怎样转成有效学习"。训练结果可以反馈给环境生产，但不能直接用低成功率判定高质量难题：先排除不可解任务、错误参考解、执行故障和 verifier 漏洞。

为了比较两条路线，我们可以考虑共用一种任务包，保留来源、能力目标、初始状态、动作/工具、重置方式、验收器、参考解、版本与执行成本。SFT 消费经过筛选的示范，在线 RL 消费任务采样接口与奖励。**这是建议的实验组织方式，尚未实现或证明优于其他设计。**

## 四、我们的研究设想与可验证实验

### 设想 A：质量验收能让规模扩展继续带来收益

假设：随着环境数量增长，去重、可解性检查和 verifier 审计可以减缓坏任务与冗余任务的累积，改善单位成本的有效产量。

做一个"少/多环境 × 基础/加强质量验收"的对照。固定来源范围和学习器，在独立任务上比较收益；同时记录构造开销与最终保留数量。分别报告固定训练预算和固定端到端预算的结果，避免一边多花构造成本、一边宣称免费提升。若收益只来自更多 token、重复曝光或更强教师，该假设不成立。

### 设想 B：同一环境池能支持两种数据生产方式

假设：共享任务及验收规范，在同一来源池上生产 SFT 示范与 RL 交互任务，可以减少重复工程，并更清楚地比较不同学习信号。

先在一个可执行领域做验证，例如仓库/终端任务。分别比较 SFT、RL、SFT→RL；SFT 实验固定基座、优化设置和训练 token 预算，RL 实验明确交互与算力预算，跨算法另报告总成本，不把不同预算口径混成公平对比。是否共享数据、是否先 SFT、是否更换教师分别作消融；不预设联合路线一定最好。

### 设想 C：按能力缺口生成，比盲目扩容更有效

假设：从独立开发集发现薄弱能力，再检索相应技能/内容并生成环境，比同预算随机增量更有效。

对比随机生成、仅按低通过率筛选、先质量检查再按能力缺口定向生成。留出未见来源、仓库或任务模板作为最终测试；最终测试不能被用于生成反馈。若只提高已见模板分数而没有跨来源收益，就不能认为建立了有效的环境迭代机制。

这些是研究假设，不是新颖性结论。Envs-FORGE、CalibForge、Agent-World、VERA 等已有反馈或难度调整思路，下一步必须比较反馈信号、被修改对象和实验控制上的实际差异。

## 五、判断"训练得好"的最低要求

- **基线与预算**：相同基座与明确预算，比较现有数据、无筛选合成、经过质量处理的合成；构造、教师采样与训练成本分别记账。
- **来源隔离**：在生成之前划分可用来源；检查仓库、模板、教程与任务派生关系。仅字符串去重不足以排除同源泄漏。
- **独立泛化**：同时报告同域未见任务与跨来源/技能组合；不要只看生成模型或训练环境自己的 verifier 分数。
- **因果拆分**：分别比较数量、质量、难度、教师、过滤和混合配方；关键实验检查重复运行的波动。
- **可用性与开放程度**：区分模型权重、轨迹数据、任务集、环境构建器和完整训练配方，明确实际能复用什么。

## 六、目录如何服务这个重点

保留原有 6 个大类、20 个小类、论文/仓库/博客表格与技术报告章节索引。开头只保留两条研究主线，以及直接相关的代表论文与公司文章。接口、沙箱、领域基准、一般审计和泛世界模拟回到原分类作支撑，按实验需要查阅，不再单独扩成平行的研究目标。

"先造环境、暂不训练"的工作仍可进入第一条主线；能否训练、训练多好是另一层验证。此处收敛的是研究重点，不把整个目录改成仅收训练论文的列表。
