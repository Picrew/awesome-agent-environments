# 从技能、需求到环境与交互数据

复核日期：2026-10-08。这里把用户关注的 Envs-FORGE、Skill2Env 一线展开，与相邻构造路线比较。表格中的“产物”描述论文方法，不自动意味着这些产物全部公开。完整版本、作者和代码状态见[主目录](../README_zh.md)。

## 技能不是只有运行时提示词这一种用途

在这组工作中，技能可以充当任务分布的来源、构造环境的约束、规划轨迹的组件，或者执行时必须遵守的契约。这几种角色需要分开；仅让模型在提示词里看到技能，不足以证明它使用了技能，也不足以证明环境生成质量。

| 工作 | 输入与构造路线 | 主要产物／验证重点 | 本轮确认的发布边界 |
| --- | --- | --- | --- |
| [Skill2Env](https://arxiv.org/abs/2609.33772) | 技能描述 → 场景化任务与可执行环境 → 示范 | 把技能知识落实为交互经验；论文展示 SFT | [研究主页](https://github.com/AllSpark-Research/AgentEnv)提供示例任务与模型；未确认完整合成流水线 |
| [Terminal-World：skills](https://arxiv.org/abs/2605.20876) | 技能组合／依赖 → 同时构造任务、环境与教师轨迹 | 强调三者语义对齐，减少没有指导的探索 | 未确认官方生成代码；与下文录制路线同名但不同工作 |
| [SkillSynth](https://arxiv.org/abs/2604.25727) | 场景作为过渡节点、技能连接场景 → 采样路径 → 实例化任务 | 控制组合与轨迹多样性，而非只增加题目数量 | 未确认官方生成代码 |
| [Terminal-Task-Gen](https://arxiv.org/abs/2602.21193) | 种子任务与技能两种生成路径 → 环境适配 → 采集与筛选 | 任务合成、轨迹工程、训练配方共同影响结果 | 有 NVIDIA 模型／数据集合；不把配套基线仓库误认成完整生成器 |
| [SKT](https://arxiv.org/abs/2608.02287) | 技能 → 任务包 → 求解、检查与修复 | 检查任务成功，也检查要求的技能是否确实被使用 | 未确认官方流水线代码 |
| [Grounded Skill-Following](https://arxiv.org/abs/2610.05161) | 将技能明确为状态、动作、转移与终止契约 | 约束执行并产生进度反馈；不是主要负责生成世界 | 论文所附仓库本轮 404，保留论文，不计入公开实现 |
| [SkillScriptBench](https://arxiv.org/abs/2610.04008) | 构建含脚本故障及受控编辑的技能包测试 | 评测智能体修复可执行技能的能力 | 这是基准构造，不能据此宣称有通用环境生成器 |

## 需求与真实工作流提供另一类输入

技能库覆盖了“能做什么”，需求和场景则约束“为什么要做、起始状态是什么、怎样算完成”。它们可以结合，但不能用技能词条数替代真实任务分布的覆盖度。

| 工作 | 核心构造对象 | 与技能路线的关系 | 需要观察的限制 |
| --- | --- | --- | --- |
| [Envs-FORGE](https://arxiv.org/abs/2608.14312) | 面向 agent 的可核验环境合成 | 与技能驱动工作共同构成环境生产线；不因名称相近而当成同一方法 | 关联 DataArc 工具包，完整论文实现定位仍不充分 |
| [NexForge](https://arxiv.org/abs/2607.14186) | 从需求生成任务，并准备文件、依赖、运行环境和示范 | 用需求约束任务分布；不只适用于终端，还涉及办公任务 | 模型发布与环境生成器发布不同；当前论文标题可能与早期检索结果不同 |
| [CLI-Universe](https://arxiv.org/abs/2606.22883) | 能力／需求蓝图 → Docker 任务 → 验证器与轨迹 | 将任务需求和可执行验收绑定 | 执行通过不能单独证明任务真实、多样且无泄漏 |
| [ClawEnvKit](https://arxiv.org/abs/2604.18543) | 自然语言 → YAML 任务、模拟服务、评分配置 | 支持按需构造评测环境，不要求先训练模型 | 固定模拟服务引擎与真实企业系统不同；评分含规则和模型检查 |
| [AgentMercury](https://arxiv.org/abs/2608.20634) | 先构建持久业务世界及跨服务不变量，再派生任务 | 将可生成任务的状态世界置于单个任务之前 | 公开样本不等于完整可执行世界库 |
| [SWE-Playground](https://arxiv.org/abs/2512.12216) | 从零合成软件项目、任务与轨迹 | 用项目结构拓宽任务类型，包括复现问题和实现库 | 合成软件和真实软件分布之间仍需验证迁移 |
| [CalibForge](https://arxiv.org/abs/2608.06352) | 候选终端任务 → 求解器试做 → 根据结果修订 | 在生成之后增加相对能力校准 | 强通过／弱失败是相对于指定求解器的关系，不是绝对难度 |

## 也可以不先造新环境，而在已有环境里生产新数据

| 输入来源 | 工作 | 实际新增的对象 |
| --- | --- | --- |
| 网页教程 | [AgentTrek](https://arxiv.org/abs/2412.09605) | 从教程提炼任务，指导浏览器回放并筛选轨迹 |
| 自主 GUI 探索 | [OS-Genesis](https://arxiv.org/abs/2412.19723) | 先发生交互，再反向构造与结果一致的任务 |
| 大量已有网站 | [InSTA](https://arxiv.org/abs/2502.06776) | 网站任务标注、执行轨迹及成功判定 |
| 真实终端录制 | [TerminalWorld：recordings](https://arxiv.org/abs/2605.22535) | 逆向恢复环境与任务，并形成分层核验的评测集 |
| GitHub 仓库与 PR | [TerminalTraj](https://arxiv.org/abs/2602.01244)、[ScaleSWE](https://arxiv.org/abs/2602.09892) | 可运行快照、测试约束、任务规格与轨迹 |
| 已有任务与不同教师 | [OpenThoughts-Agent](https://arxiv.org/abs/2606.24855) | 数据配方、混合与筛选策略，研究哪些经验更有效 |

两个 Terminal World 分别使用 `terminal-world-skills` 与 `terminalworld-recordings` 工作标识，避免把一篇论文关联到另一篇的代码。

## 用同一组问题比较，而非只比生成数量

以下是本调研的分析框架，未宣称为任何一篇论文的共同结论：

1. **来源覆盖**：技能、需求、仓库、录制分别怎样采样和去重？覆盖的是语义能力还是表面措辞？
2. **构造产物**：是否同时具备指令、初始状态、工具、终止条件、参考解及验证器？只合成指令时不要称为完整环境。
3. **验证层次**：语法／配置有效、能启动、有参考解、任务符合需求、验证器抗投机，需要分别记录。
4. **经验质量**：任务可解不代表轨迹有教学价值；要观察技能实际使用、步骤冗余、错误恢复与教师偏差。
5. **复用能力**：公开的是方法代码、打包环境、数据切片、镜像还是模型？每一种都值得记录，但不能互相替代。
6. **评估隔离**：按技能来源、模板、网站、仓库或时间划分，而不仅在生成结果上随机切分。

因此，比较实验宜同时记录有效任务数、环境家族数、轨迹数、每阶段验收率与成本。只有在交互后端、验证方式和数据划分可比时，才讨论规模对下游收益的影响。
